# Сборка ЭХО на GitHub — пошаговая инструкция

> Бюджет проекта: **0 ₽**. Все шаги — только на бесплатных сервисах.
> Результат: после каждого обновления файлов GitHub сам собирает APK, который вы скачиваете и ставите на телефон.
> Концепция, от которой исходим: **ЭХО** — «Ты видишь не людей вокруг. Ты видишь музыку, которая сейчас живёт вокруг тебя».

## Шаг 0. Что грузим на GitHub, а что — НИКОГДА

Загружаем ровно **18 файлов** из папки `D:\Проекты\Echo\Эхо для автоклав`:

| Папка/файл | Зачем нужен |
|---|---|
| `.github\workflows\build-apk.yml` | рецепт сборки APK для GitHub Actions |
| `app\` (вся папка, 5 файлов внутри) | исходники Android-приложения + манифест + gradle-модуль |
| `build.gradle.kts` (корень) | общий конфиг сборки |
| `settings.gradle.kts` | структура проекта |
| `gradle.properties` | настройки Gradle |
| `.gitignore` | правила игнорирования (пригодится позже) |
| `README.md` | описание проекта |
| `echo_server.py` | сервер |
| `echo_pc.py` | ПК-узел (музыка Windows) |
| `echo_tunnel.py` | туннель для улицы |
| `templates\` (2 файла) | веб-сонар и пульт |
| `requirements.txt`, `echo_config.example.json` | описания зависимостей/конфига |

**НИКОГДА не загружайте** (сайт GitHub игнорирует `.gitignore` — следить надо руками):

- 🚫 **`echo_config.json` — там живой ключ Gemini.** Попадёт в публичный репозиторий = ключ украдут боты за минуты. Случайно загрузили → сразу перевыпустите ключ в Google AI Studio и удалите файл из репозитория.
- 🚫 `echo_memory.db` — ваша личная история прослушиваний.
- 🚫 `cloudflared.exe`, `cloudflared-master\` — тяжёлые, для сборки не нужны.
- 🚫 `v1.zip`, `v8\`, `v9\` — старые версии.
- 🚫 `create_echo_project.bat` — одноразовый скрипт, больше не нужен.
- 🚫 `__pycache__\`, `*.log`, `server_test.*` — технический мусор.

## Шаг 1. Аккаунт GitHub (~2 минуты)

1. Откройте **https://github.com** → **Sign up**.
2. Email + пароль + ник. Подтвердите почту.
3. Бесплатно и навсегда. Карту вводить не надо.

## Шаг 2. Репозиторий (~2 минуты)

1. После входа нажмите **+** (правый верх) → **New repository**.
2. **Repository name:** `echo-radar`.
3. **Public** — рекомендуется: для публичных репозиториев сборки Actions **не ограничены**. (Private тоже работает: 2000 бесплатных минут в месяц — это ~400 сборок, но Public проще.)
4. Галочку **«Add a README» НЕ ставьте** (README уже есть в проекте).
5. **Create repository**.

## Шаг 3. Загрузка файлов (~10 минут)

1. На странице пустого репозитория найдите ссылку **«uploading an existing file»** и нажмите её.
2. Откройте папку `D:\Проекты\Echo\Эхо для автоклав` рядом с браузером.
3. Перетащите в окно браузера: папки `.github`, `app`, `templates` **и** корневые файлы из таблицы шага 0 (`.gitignore`, `README.md`, `build.gradle.kts`, `settings.gradle.kts`, `gradle.properties`, `echo_server.py`, `echo_pc.py`, `echo_tunnel.py`, `requirements.txt`, `echo_config.example.json`). Браузер сохранит структуру папок — не пугайтесь пути `app/src/main/java/...`, так и должно быть.
   ⚠️ **Папки с точкой в начале (`.github`) часто НЕ перетаскиваются в браузер.** После загрузки проверьте, что в репозитории есть папка `.github` с файлом `workflows/build-apk.yml` внутри. Если её нет — не перетаскивайте, а создайте вручную: **Add file → Create new file**, в поле имени наберите `.github/workflows/build-apk.yml` (слэши сами создадут папки), вставьте содержимое этого файла и сделайте Commit. Затем удалите случайную копию workflow из корня, если она появилась.
4. Дождитесь, пока все 18 файлов появятся в списке.
5. ⚠️ **Финальная проверка перед коммитом:** в списке НЕТ `echo_config.json`, `echo_memory.db`, `*.exe`, `*.apk`, `*.zip`.
6. Внизу нажмите **Commit changes** (текст сообщения можно оставить как есть).

## Шаг 4. Сборка (~5–8 минут, автоматически)

1. Загрузка файлов = push → сборка стартует **сама**.
2. Откройте вкладку **Actions** — увидите «Сборка ЭХО Android APK» с жёлтой точкой (идёт) или зелёной галочкой (готово).
3. Если почему-то не стартовала: **Actions** → слева выберите workflow → **Run workflow** → **Run workflow**.
4. Первая сборка самая долгая (скачивает Gradle и зависимости), следующие быстрее.

## Шаг 5. Скачать APK (~1 минута)

1. Откройте успешную (зелёную) сборку в Actions.
2. Прокрутите вниз до блока **Artifacts**.
3. Скачайте **echo-radar-debug-apk** — это ZIP-архив. Внутри лежит **`echo-radar-debug.apk`**.
4. Артефакты хранятся **30 дней**, потом исчезают — не откладывайте.

## Шаг 6. Установить на телефон (~3 минуты)

1. Перекиньте `echo-radar-debug.apk` на телефон: Telegram («Избранное»), USB-кабель или облако.
2. Откройте файл на телефоне → **Установить**.
3. Android спросит про «установку из неизвестных источников» — разрешите для того приложения, через которое открыли файл (это разовая настройка).
4. Запустите ЭХО, разрешите доступ к уведомлениям (приложение читает только музыкальные уведомления плееров).

## Шаг 7. Как обновлять приложение

1. Меняете файлы проекта (у себя или прямо на GitHub: **Add file → Upload files** в нужной папке).
2. Commit changes → сборка стартует сама → новый APK в Artifacts.
3. Совет: при заметных изменениях поднимайте `versionCode` и `versionName` в `app/build.gradle.kts` — так видно, какая версия на телефоне.

⚠️ **Нюанс подписи (важно!):** каждая сборка на GitHub подписывается *новым* отладочным ключом, поэтому поверх старой версии телефон может ответить «Приложение не установлено». Лечение: удалите старую версию ЭХО и поставьте новую. Когда надоест — попросите меня добавить релизную подпись через GitHub Secrets (это тоже бесплатно).

## Шаг 8. Если сборка упала (красный крест)

1. Actions → красная сборка → клик по ней → клик по упавшему шагу (обычно «4. Сборка отладочного APK»).
2. Прочитайте последние строки лога. Типовые причины:
   - **Забыли файл** — чаще всего `app\build.gradle.kts` или корневые gradle-файлы. Сверьтесь со списком шага 0 → Upload files.
   - **Файл не в той папке** — например, `build-apk.yml` оказался в корне, а не в `.github\workflows\`.
   - Опечатка в имени файла.
3. Пришлите мне текст ошибки из лога — разберу и скажу, что править.

**Сборки вообще нет в Actions (вкладка пустая):** значит, файл workflow не в том месте — он обязан лежать по пути `.github/workflows/build-apk.yml`, а не в корне. Создайте его там через Add file → Create new file (см. предупреждение в шаге 3) и удалите копию из корня.

## Самокритика этой инструкции (по вашему рабочему правилу)

- **Главный риск — ручная загрузка.** Через сайт легко забыть файл или зацепить лишний. Смягчение: чек-лист в шаге 0 и проверка перед коммитом. Когда надоест таскать файлы руками — поставьте **GitHub Desktop** (desktop.github.com, бесплатно, без командной строки): «File → Add local repository → Publish», и обновления станут одним кликом.
- **Каждая сборка = новый отладочный ключ** → переустановка поверх старой не работает (описано в шаге 7). Для тестового этапа терпимо; для «поставил и забыл» нужна релизная подпись через Secrets — сделаем по запросу.
- **Public-репозиторий = код виден всему миру.** Для проекта с нулевым бюджетом это честная цена, но она безопасна только при строгом соблюдении шага 0 (секреты не грузим). Приватный репозиторий — запасной вариант, минусы: лимит 2000 минут/мес (для вас всё равно с запасом) и чуть больше настроек.
- **Инструкция описывает сборку, но не запуск сервера** — сервер и телефон живут по README.md (разделы 3–8). Здесь это сознательно не дублируется.
- **Что не учтено:** никакой аналитики сборок и автотестов в CI нет — по мере роста проекта стоит добавить хотя бы проверку компиляции Python (`py_compile`) отдельным шагом. Бесплатно, попросите — сделаю.
