# ЭХО (Echo Radar)

> «Ты видишь не людей вокруг. Ты видишь музыку, которая сейчас живёт вокруг тебя».

## 1. О проекте

**ЭХО** — приложение музыкального присутствия. Вместо аватарок и статусов — музыка:
трек, играющий у человека прямо сейчас, становится сигналом на ночном сонаре,
а ИИ-куратор даёт слушателю поэтичное имя и совместимость вкуса.

Состав системы:

- **Android-приложение** — сонар в кармане: читает играющую музыку и показывает сигналы вокруг;
- **Сервер** `echo_server.py` — сердце ЭХО: Python + SQLite, принимает сигналы и хранит эфир;
- **Веб-интерфейс** — тот же сонар в браузере ПК или планшета.

Четвёртый участник — **ПК-узел** `echo_pc.py`: он сообщает серверу, что играет на Windows,
и печатает входящие импульсы прямо в консоль.

## 2. Архитектура

```
   Android-приложение              браузер (ПК, планшет)
   (сонар в кармане)               http://<IP>:8080/app
          │                               │
          │        HTTP + JSON            │
          ▼                               ▼
       ┌──────────────────────────────────────┐
       │      echo_server.py  ←→  SQLite      │
       │      (echo_memory.db — память эфира) │
       └──────────────────────────────────────┘
                     ▲
                     │ HTTP
           echo_pc.py — ПК-узел
           (музыка Windows через SMTC)

   ~~~ UDP-маяк автопоиска ~~~
   echo_server.py каждые 3 секунды вещает в локальную сеть
   «ECHO_SERVER_DISCOVERY:8080» (порт 8888) — и телефон находит
   сервер сам, без ручного ввода адреса.
```

## 3. Быстрый старт

Нужен только Python (серверу достаточно 3.8+):

```bash
python echo_server.py
```

**Проще всего — двойной клик по `RUN-SERVER.bat`** в папке проекта (откроется окно, сервер запустится).

> ⚠️ Если в консоли `python` не находится («Python was not found… Microsoft Store») — это
> типичная болезнь Windows: настоящий Python установлен, но не прописан в PATH.
> Работает команда **`py echo_server.py`** (лаунчер `py` есть в системе всегда) — или просто bat-файл выше.
> Постоянное лечение: Параметры → Приложения → Дополнительные параметры приложений →
> Псевдонимы выполнения приложений → выключить `python.exe` и `python3.exe`,
> а Python добавить в PATH при переустановке (галочка «Add python.exe to PATH»).

Сервер поднимется на порту 8080 и сам напечатает свои адреса в консоли.

**Брандмауэр Windows.** При первом запуске сервера система спросит про доступ —
нажмите «Разрешить доступ». Либо один раз выполните от имени администратора:

```
netsh advfirewall firewall add rule name="Echo Radar" dir=in action=allow protocol=TCP localport=8080
```

**Как узнать свой IP:** выполните `ipconfig` и возьмите строку «IPv4-адрес»
(например, `192.168.1.5`) — это адрес вашего ПК в домашней сети.

## 4. Установка приложения на телефон

**Путь A — GitHub Actions (без Android Studio):**

1. Залейте репозиторий на GitHub.
2. Откройте вкладку **Actions** и дождитесь успешной сборки «Сборка ЭХО Android APK».
3. Скачайте artifact **echo-radar-debug.apk**.
4. Передайте APK на телефон (мессенджер, облако, USB-кабель).
5. Установите, разрешив установку из неизвестных источников.

**Путь B — Android Studio:**

Откройте папку проекта (теперь это полноценный Gradle-проект), включите на телефоне
USB-отладку и нажмите **Run ▶**.

> На локальной машине нет Java и Android SDK, поэтому собрать APK прямо здесь
> не получится — используйте GitHub Actions или Android Studio.

## 5. Первый запуск

1. Телефон и ПК должны быть в **одной Wi-Fi сети**.
2. Приложение само найдёт сервер по UDP-маяку (занимает до нескольких секунд).
   Если не нашло — кнопка **⚙** → введите `http://<IP-ПК>:8080`.
3. Дайте приложению **доступ к уведомлениям** — оно читает только музыкальные
   уведомления плееров, ничего больше.
4. При первом запуске ЭХО спросит согласие на присутствие. По умолчанию вы
   **невидимка** (opt-in). «Открыться для музыки» включает эфир; кнопка
   «● Присутствие» мгновенно выключает его вместе с историей прослушивания.
5. Включите музыку в любом плеере — трек тут же появится на сонаре.

## 6. Музыка с ПК

```bash
python echo_pc.py
```

Или двойной клик по **`RUN-PC-MUSIC.bat`** (сервер должен быть уже запущен).

Авторежим читает играющий трек через SMTC — то самое окошко, которое Windows
показывает при нажатии клавиш громкости. Сменился трек — узел сам отправляет его в эфир.

- Сервер на другой машине: `python echo_pc.py --server http://<IP-ПК>:8080`
  (или задайте переменную окружения `ECHO_SERVER`).
- Для авторежима нужны пакеты winrt:
  `pip install winrt-runtime winrt-Windows.Media.Control winrt-Windows.Foundation`
  (проверено на Python 3.13 — устанавливается). Без них узел сам предложит ручной режим.
- `--manual` — ручной режим: вводите «Исполнитель — Название» построчно.
- `--once` — показать текущий трек и выйти (быстрая проверка, что SMTC читается).
- `--zone` — зона сонара (по умолчанию «Вечерняя улица»), `--interval` — период опроса.
- Входящие импульсы печатаются прямо в консоль: «🌙 Импульс ✦ от эфира».

## 7. Музыка с телефона на ПК

Откройте в браузере ПК `http://<IP>:8080/app` — веб-версия сонара. Пульт куратора
с настройками ИИ живёт на `http://<IP>:8080/`.

## 8. Тест-чеклист

Полный контур считается рабочим, когда:

1. Трек с ПК виден на радаре телефона.
2. Трек с телефона виден в веб-интерфейсе ПК.
3. Реакция с телефона доходит до консоли `echo_pc.py` («🌙 Импульс … от эфира»).
4. Реакция из веб-интерфейса показывает баннер на телефоне.
5. «Призрачный след» появляется примерно через 5 минут после того, как устройство замолчало.

Автоматическая проверка связки без телефона: `python tests/roundtrip_test.py`
(19 проверок: трек туда, импульс обратно, opt-out, приватность, валидация).
Тот же тест выполняется в GitHub Actions перед сборкой APK.

## 9. Туннель для улицы

```bash
python echo_tunnel.py
```

Или двойной клик по **`RUN-TUNNEL.bat`** (сервер должен быть уже запущен).

Скрипт поднимет публичный HTTPS-адрес через Cloudflare (trycloudflare) — без белого IP
и регистрации. Адрес вида `abc123.trycloudflare.com` введите в ⚙ приложения, и сонар
заработает через мобильный интернет.

Туннель публичный: задайте `ECHO_API_TOKEN` на сервере и введите тот же токен в
приложении (⚙ → «Токен туннеля») и в веб-сонаре (🔑). Токен хранится только у
клиента, в HTML страниц он не попадает. Без него GET и POST эфира вернут 401.
Для ПК-узла: `python echo_pc.py --token <токен>`.

## 10. Переменные окружения

| Переменная | Где используется | Что делает |
|---|---|---|
| `PORT` | echo_server.py | порт сервера (по умолчанию 8080) |
| `ECHO_API_TOKEN` | echo_server.py | защита **всех** запросов при публичном туннеле |
| `ECHO_ALLOW_EXTERNAL_AI=1` | echo_server.py | явный opt-in на внешний ИИ (по умолчанию выключен) |
| `GEMINI_API_KEY` | echo_server.py | ключ внешнего ИИ, читается только при opt-in выше |
| `ECHO_SEED_DEMO=1` | echo_server.py | добавить демо-слушателей в эфир |
| `ECHO_SERVER` | echo_pc.py | адрес сервера по умолчанию |

Куратор образов по умолчанию работает **локальной математикой** на стандартной
библиотеке: без платных API, без сетевых задержек и без ключей в репозитории.

## 11. Структура проекта

```
app/src/main/…     Android-приложение (Kotlin + Compose)
templates/         веб-интерфейсы: dashboard.html (пульт) и pwa.html (сонар)
echo_server.py     сервер: REST API + SQLite + UDP-маяк
echo_pc.py         ПК-узел: музыка Windows → эфир, импульсы ← эфир
echo_tunnel.py     публичный туннель Cloudflare
echo_memory.db     база SQLite (создаётся при первом запуске сервера)
tests/             roundtrip_test.py — связка Android ↔ сервер ↔ PWA в обе стороны
RUN-SERVER.bat     запуск сервера двойным кликом
RUN-PC-MUSIC.bat   запуск ПК-узла двойным кликом
RUN-TUNNEL.bat     запуск туннеля двойным кликом
```
